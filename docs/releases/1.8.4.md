# MFG Unlock 1.8.4 — MFG on DLSS-G Versions Without a Profile

This release unlocks MFG on a DLSS frame generation file the addon has no exact profile for, when that file has the same gate as every version reviewed so far. It fixes Assassin's Creed IV Black Flag Resynced, whose menu kept the MFG options locked, and keeps MFG working when NVIDIA ships a new version.

**Our recommendation stays the same: prefer XMX in games with native DLSS frame generation**, and keep the XeMFG backend for games without it.

## Why MFG stayed locked

To offer 3x and more on RTX 40, the addon changes two compares inside NVIDIA's frame generation file (`nvngx_dlssg.dll`), so its multi-frame path runs on Ada. Since 1.4.4 it only does this on files it knows exactly: the same build, size and code as a reviewed version. Any other file was refused.

Assassin's Creed IV Black Flag Resynced loads its own copy of version 310.6, a rebuild of a version the addon knows. Its code differs slightly, so it was refused, and the game offered 2x only, with XMX and with NVIDIA's generator. The same would happen to every game after NVIDIA updates its frame generation download, until a release added the new version.

## The generic gate

When a file has no exact profile, the addon now checks it the way every reviewed version was checked. It changes the file only if:

- it is a version 310 file from NVIDIA, and
- its code has exactly the two compares every reviewed 310 version has, with the same shape.

A file with any other number or shape of compares is refused, as before. The log names this case: `generic gate (no exact profile for this provider)`. Files with an exact profile are unchanged.

To turn it off, select **Generic provider gate: Off** in the panel's advanced settings, or add `[DLSSG] GenericGate=0` to `MFGAdaUnlock.ini`, and restart the game.

On the development PC, the check found the same two places as the disassembler on all 20 copies of the file installed there. It accepted 15. It refused three: Resident Evil Requiem's 310.3 (four compares), The Last of Us Part II's 310.1 (three) and the driver's 310.2.1 (none). These games use NVIDIA's newer download, which has an exact profile.

## Compatibility

Existing configuration is kept. The new setting is on by default and only acts on files without an exact profile.

## Known limitations

- **Once Human:** its `nvngx_dlssg.dll` has the timestamp of the 310.3 build, whose gate has four compares, so XMX likely stays at 2x.
- The limitations of [1.8.3](1.8.3.md) still apply.

## Validation

The automated suite ran **209 tests: 206 passed and 3 optional tests were skipped**, as in earlier releases. A new test covers the generic gate: the reviewed pair is accepted in either order, and no compare, one, three, four, two of the same shape, other opcodes, other values and a compare cut at the section's end are refused.

Tested by playing on an RTX 4070 SUPER: **Assassin's Creed IV Black Flag Resynced** unlocks MFG through the generic gate, with XMX and with NVIDIA's generator. Streamline accepted 4x and 5x, where it refused them before.

## Installation and rollback

Close the game, replace the previous addon with **renodx-mfgunlock.addon64**, keep only one MFG Unlock addon installed, and restart.

For rollback, close the process, restore your previous addon or the [1.8.3 release](https://github.com/mavismmg/MFGAdaUnlock-RenoDx/releases/tag/1.8.3), and restart.

## Building this version

As in 1.7.0: the addon is the `mfgunlock_native_xemfg` target of `tests/CMakeLists.txt`, published as `renodx-mfgunlock.addon64`; see [Building the XeMFG backend](../../README.md#building-the-xemfg-backend).
