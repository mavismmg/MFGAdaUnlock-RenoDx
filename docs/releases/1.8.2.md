# MFG Unlock 1.8.2 — More Games with XMX

This release makes XMX work in Dying Light 2, Alan Wake 2 and Phantom Blade Zero. All three could look like XMX was selected while it was generating nothing, or while NVIDIA's generator was still doing the work. It also adds one narrow XeMFG fix for Titans of the Tide.

**Our recommendation stays the same: prefer XMX in games with native DLSS frame generation**, and keep the XeMFG backend for games without it.

## XMX mode

### Fixed

- **XMX could silently fall back to NVIDIA's generator (Dying Light 2, Alan Wake 2).** NVIDIA can run its generator from a copy it downloads to `C:\ProgramData\NVIDIA\NGX\models`. When that copy was already loaded before the addon started, it never received the XMX hook, so the game kept using NVIDIA's generator while XMX was selected. Every copy of the generator now gets the hook, however it is found.
- **XeFG refused every frame when depth and motion differ in size (Phantom Blade Zero).** The game sends depth at 1488x836 and motion vectors at 1485x836. Intel's model requires the same size for both and returned error `-4` on every frame, so the panel showed *XeFG returned an error*. XMX now gives the model the area both inputs share, using the areas the game declares when they are valid. Games whose depth and motion already match are not affected.

### The panel says when XMX is bypassed

If the hooks are in place, XMX is never called and frames are still being generated, then NVIDIA's generator is doing the work. The panel now shows this as *NVIDIA is generating*, with a card titled *XMX is not being used*. The support report includes it as `xmx_bypassed`.

## XeMFG backend

- **XeMFG can now take over in Titans of the Tide.** This game's Streamline has no DLSS-G plugin, and XeMFG refused its output because it could not take over presentation the usual way. A profile for this game now accepts that case. It applies only to `Ghost-Win64-Shipping.exe`, only when Streamline reports the plugin as missing after loading its plugins, and never when the game runs its own XeFG.
- **A clearer message for other games in this situation.** XeMFG now says the game's Streamline has no DLSS-G plugin and that restarting will not change that.

## Documentation

- The README now covers ReShade's error **1114** when loading the addon. The usual cause is the addon being listed under `DisabledAddons` in `ReShade.ini`.
- **Correction: the XMX measurements did not show input latency.** The column labeled *Average latency* was PresentMon's `DisplayLatency` averaged over every displayed frame. PresentMon counts generated frames differently on each route, so the column cannot be compared between XMX, DLSS-G and XeMFG. It does not show that XMX at 4x had lower input latency than generation off. The column is now labeled for what it is. Thanks to the player who questioned it.

## Compatibility

Existing configuration is kept, and no default changed.

## Known limitations

- **Titans of the Tide:** this fix has not been confirmed in the game yet. Its reporter will test this version.
- **Phantom Blade Zero with XeMFG on an RTX 5090 D:** one report stops right after the first Present, and the cause is unknown. This release does not address it. Logs, a crash dump and a test in SDR would help.
- **XMX** still does not pass the view matrix or a separate UI input to Intel's model and assumes fixed resource states. It reads input subrects only when depth and motion differ in size.
- **XMX** does not run in Vulkan games, where NVIDIA's generator keeps running, or in games that use XeMFG through FSR or the DLSS-SR input.

## Validation

The automated suite ran **207 tests with no failures**. Three optional tests were skipped, as in earlier releases.

New automated tests cover hooking each copy of the generator once, detecting a bypassed XMX, choosing the area shared by depth and motion, and the conditions of the Titans of the Tide profile.

Tested by playing on an RTX 4070 SUPER, driver 621.01, with XMX:

- **Dying Light 2:** generates with XMX.
- **Alan Wake 2:** generates with XMX.
- **Phantom Blade Zero:** generates with XMX at 2560x1440.

Not confirmed in a game at release time: the Titans of the Tide profile, and the panel's *XMX is not being used* card, which no tested game has triggered since the hook fix. Thanks to the players who sent logs. They made these fixes possible.

## Installation and rollback

Close the game, replace the previous addon with **renodx-mfgunlock.addon64**, keep only one MFG Unlock addon installed, and restart.

For rollback, close the process, restore your previous addon or the [1.8.1 release](https://github.com/mavismmg/MFGAdaUnlock-RenoDx/releases/tag/1.8.1), and restart.

## Building this version

As in 1.7.0: the addon is the `mfgunlock_native_xemfg` target of `tests/CMakeLists.txt`, published as `renodx-mfgunlock.addon64`; see [Building the XeMFG backend](../../README.md#building-the-xemfg-backend).
