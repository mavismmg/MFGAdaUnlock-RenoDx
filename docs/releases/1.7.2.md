# MFG Unlock 1.7.2 — XeMFG Focus Fix

This release fixes XeMFG not coming back after a game pauses frame generation, as Crimson Desert does when it loses focus, and makes a log message about early loading say what is actually wrong.

## XeMFG backend

- **Fixed: frame generation did not come back after alt-tab or the screen saver in Crimson Desert.** The game stops its Reflex waits while it has no focus, and XeLL accepts only consecutive frame numbers, so it refused the first wait after the pause. The game reacted by leaving Reflex, Ray Reconstruction and frame generation off, with a noisy and banded image, until it was closed. Applying video settings in that state also saved them as off. The addon now passes the skipped frame numbers through XeLL before that wait, which took under 1 ms in the game.
- **Clearer message when XeMFG cannot own presentation.** The log and panel used to ask for early addon loading in every case. They now say so only when it can help, and report separately when the game's Streamline lacks a required function or when no Streamline was found. A new `native_presentation_not_owned` log entry lists what was found.
- **No false alarm from D3D11 swap chains.** A small D3D11 test swap chain, like the one created when Dying Light 2 starts, no longer produces that message. XeMFG only runs on D3D12, and those chains are still created normally.
- **New diagnostics.** The log now records what a game does with its swap chain before the first frame (`native_swapchain_setup`) and any interface the addon's swap chain refuses (`native_swapchain_interface_refused`).

## Compatibility

Existing configuration is kept and no default changed. The DLSS-G backend is unchanged apart from the version.

## Known limitations

- Other games that stop their waits during a pause should benefit from the same fix, but only Crimson Desert was tested for it.
- Dying Light 2 with XeMFG still closes on startup, right after the addon takes over its swap chain, and the cause is not known yet. The game was not available for testing here. Logs from this version should help find the cause.

## Validation

The automated suite ran **202 tests with no failures**, including a new test for frame numbers skipped during a pause. Three optional tests were skipped, as in earlier releases.

In Crimson Desert on NVIDIA driver 621.01 (RTX 4070 SUPER), the final build went through two alt-tabs: frame generation came back after 1 to 3 seconds each time, XeLL refused no wait, and passing up to 118 skipped frame numbers took under 1 ms. A test build with the same fix also came back normally from the screen saver. Output and source frame times stayed within the range of 1.7.1 sessions, in a short comparison that is not a precise measurement.

## Installation and rollback

Close the game, replace the previous addon with **renodx-mfgunlock.addon64**, keep only one MFG Unlock addon installed, and restart.

For rollback, close the process, restore your previous addon or the [1.7.1 release](https://github.com/mavismmg/MFGAdaUnlock-RenoDx/releases/tag/1.7.1), and restart.

## Building this version

As in 1.7.0: the addon is the `mfgunlock_native_xemfg` target of `tests/CMakeLists.txt`, published as `renodx-mfgunlock.addon64`; see [Building the XeMFG backend](../../README.md#building-the-xemfg-backend).
